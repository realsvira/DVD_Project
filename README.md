# ML-Driven PVT Variation Aware Leakage Estimation

Digital VLSI Design course project. The course specification (`DVD_ML_PROJECT.pdf`, not included in this repository) is the primary reference.

**Team:** Saumya Vira, Anish Toshniwal, Shrenil Patel, Het Selarka.

**What this project does:**
- **Part A:** learns the four terminal currents (Id, Ig, Is, Ib) of single transistors (NMOS/PMOS, ON/OFF) from 40,000+ ngspice simulations under PVT variation.
- **Part B:** predicts the leakage of INV, NAND2, NOR2, AND2 and OR2 hierarchically from those transistor models (18 gate/input cases × 200 PVT corners).
- **Part C:** composes the gate models into the assigned **3-bit carry-lookahead adder** (36 gates, 192 transistors) and validates each level against SPICE.

| Item | Team value |
|---|---|
| Model file | **45nm HP**: PTM 45 nm high performance, metal gate / high-k (`models/45nm_HP.pm`) |
| Nominal VDD | **1.0 V** (sampled 0.9–1.1 V) |
| Channel length / widths | L = 45 nm; W = 45–360 nm |
| Test circuit | **3-bit carry-lookahead adder** (inputs A, B, Cin: all 128 combinations) |
| Simulator / language | ngspice (44.2 for the submitted results; 45.2 also verified) / Python ≥ 3.11 (3.13 used), Linux |

## Final results (final models, independent evaluation data)

| Level | Median error | 95th-percentile error | Mean accuracy* |
|---|---|---|---|
| Transistor (fresh test, spec distribution, 4 cases × 4 terminals) | 0.61 % | 3.4 % | 98.56 % |
| Gates (18 cases × 200 **new** PVT corners) | 0.78 % | 3.0 % | 98.93 % |
| 3-bit CLA (all 128 input combinations × 200 **new** PVT corners) | 0.58 % | 2.2 % | **99.22 %** |

- **99 % target:** reached at circuit level; **not** reached at gate (98.9 %) or transistor (98.6 %) level.
- **Official Part B/C corners:** gates 98.97 %, CLA 99.29 %.

- **Requirement → file map:** see [What is in this repository](#what-is-in-this-repository); `run_all.py --mode verify` also writes `reports/deliverables_checklist.md`.
- A Markdown/HTML version of the report (`reports/FINAL_REPORT.md/.html`) is generated by `scripts/z3_build_report.py` after a full run.

## Conventions and design decisions

* **Current sign:** every terminal current is positive when it flows **into** the device.
  ngspice reports `i(Vx)` flowing + to − through the source, so I_terminal = −i(Vx).
* **Units (SI, as in the BSIM4 cards):** W, L, toxe, xj in m; vth0 in V; ndep in cm⁻³;
  u0 in m²/(V·s); temperature in °C; currents in A.
* **Process variation is written into a fresh model card per sample.**
  Do not use `altermod` for `toxe`. ngspice 44.2 accepts the new value but does not recompute the
  oxide-derived terms, so gate and channel currents come out wrong by up to ~5×. This was measured
  in this project against fresh netlists. vth0, ndep, u0 and xj behaved correctly under `altermod`,
  but the project uses one trusted code path for all five parameters.
* **Only `toxe` is varied.** toxp, toxm and toxref keep their nominal values, as the spec lists only toxe.
* **Model copy:** `models/45nm_HP.pm` (from the course's `Model Files-20261112.zip`; the older copy in the
  Project 1 archive differs only in whitespace). Its SHA-256 is fixed in `config/project.toml` and checked.
* **Simulator note:** ngspice reports the `version = 4.0` BSIM4 cards as "BSIM4v5". The printed
  "No compatibility mode selected!" is informational only.
* **Reproducibility:** all random seeds live in `config/project.toml` under `[seeds]`.

## Part A1: transistor simulation engine

### Modules
| File | Role |
|---|---|
| `src/leakage/simulator.py` | `NgspiceSimulator.run_op(circuits, vectors)`. A general batch DC operating-point engine, reused later for gates and the CLA. |
| `src/leakage/transistor.py` | Single-FET netlist generator and API: `make_inputs`, `sample_inputs`, `transistor_circuit`, `example_netlist`, `simulate_transistors`, `simulate_transistor`, `kcl_residual`, `kcl_ok`. |
| `src/leakage/spice.py` | Model-card read/edit, ngspice discovery, ASCII raw-file parser (`parse_raw_ascii`). |
| `scripts/a1_smoke_test.py` | Four-case nominal smoke test plus a 192-point corner sweep. Also writes the example netlists. |
| `netlists/transistor/*.cir` | Stand-alone example netlist for each case (deliverable 2). |

### How a simulation runs
1. Each sample becomes a self-contained circuit containing:
   - the required `.options` line;
   - `.temp`;
   - one FET with `L = 45 nm`;
   - a separate voltage source on each of d, g, s and b;
   - a copy of that device's own `.model` card from `45nm_HP.pm`, with the sample's vth0/toxe/ndep/u0/xj written in.

   The other device's card is left out, and the supplied `.pm` file is only ever read (a test checks its SHA-256).
2. About 200 circuits share one ngspice process. A driver runs `source s<k>.cir` → `op` →
   `write o<k>.raw i(vd) i(vg) i(vs) i(vb)` for each one, and up to 11 processes run in parallel.
3. Values come from ngspice's **ASCII raw files** (structured, full double precision), never from the printed log.
4. A circuit that fails writes no raw file. It is marked `failed` and re-run on its own to collect
   its exact error messages. Other circuits are unaffected (tested with an unknown-model circuit and a singular-matrix circuit).
5. Results are identical (relative difference < 1e-9) to running each example netlist on its own (tested).

### Sign convention
Every current is **positive when it flows into the device terminal**: `I_X = -i(VX)`.
At the nominal NMOS ON point, `i(vd) = -1.1208e-04`, so Id = +1.1208e-04 A, flowing into the drain.

### Kirchhoff check
The pass criterion is |Id + Ig + Is + Ib| ≤ 1e-6·max|I| + 10 fA.

At the nominal points the residual is 1e-17 A or less. When every current is tiny (≤ 1e-12 A, e.g. Vd = Vs), ngspice's BSIM4 code leaves a fixed residual of about 1.2 fA. That figure did not change with gmin, reltol or vntol (measured), so it comes from the device model, not from solver tolerances.

### How this differs from the supplied `22n_NMOS_ON.net`
That file was used for reference only. Its Linux `.include` path, `GMIN=1e-20` options, 22 nm sizes, Vg-referenced-to-`Ref` VDD sweep and `dc TEMP` sweep were all replaced:
- every sample gets one `op`;
- VDD, T, W, Vd, Vs and the process parameters are independent inputs;
- the required options line is used;
- the model card is embedded, so the netlist contains no paths.

## Part A1: dataset generation

Script: `scripts/a1_generate_datasets.py`; logic in `src/leakage/dataset.py`.

```bash
# 20-sample smoke test per case (run after any code change)
.venv/bin/python scripts/a1_generate_datasets.py --smoke
# quick end-to-end run: 200 samples per case into data/transistor_small/
.venv/bin/python scripts/a1_generate_datasets.py --small
# full run: 10,000 valid samples per case into data/transistor/ (smoke test runs first)
.venv/bin/python scripts/a1_generate_datasets.py
```
Other options: `--cases nmos_off pmos_off`, `--n 2000`, `--out data/tmp`, `--batch 500`,
`--workers 6`, `--max-extra 200`, `--skip-smoke`, `--no-progress`.

**Sampling** (spec Section 4):
- VDD ~ U(0.9, 1.1) V, drawn first.
- T ~ U(−40, 125) °C.
- W ~ U(45, 360) nm.
- Vd and Vs: each drawn independently from U(0, VDD).
- vth0/toxe/ndep/u0/xj: each drawn independently from U(±10 %) around that device's own nominal value.
- Vg and Vb are set by the case.

**Reproducibility and stable IDs:**
- Sample *k* of a case is drawn from `default_rng([case_seed, k // 1000])`, and every block of 1000 is always drawn in full.
- So sample *k* gets identical inputs whatever `--n` is, and the small run is an exact prefix of the full run.
- Per-case seeds are `seeds.data + 100·case_index` (1001, 1101, 1201, 1301).
- Inputs are rounded to the 12 significant digits written into the netlist, so the CSV holds exactly what was simulated.

**Robustness:**
- Each batch (`--batch`, default 1000) is saved once, atomically, to `data/transistor/_shards/<case>/`.
- Rerunning the same command resumes: saved IDs are skipped, so nothing is duplicated (tested by deleting shards). Ctrl+C is safe.
- Failed simulations keep NaN currents, never zeros. They are listed in `failures.csv`, and the next unused IDs are simulated until there are N valid samples. The run stops if more than `--max-extra` replacements would be needed.
- Parallelism is a fixed pool of `--workers` ngspice processes, 11 by default.

**Outputs** in `data/transistor/`:

| File | Content |
|---|---|
| `<case>.csv` | the dataset: columns `vdd, temp, w, vd, vs, vg, vb, vth0, toxe, ndep, u0, xj, id, ig, is, ib`, sorted by sample ID |
| `<case>_index.csv` | maps each row to its sample ID, plus that row's Kirchhoff sum |
| `failures.csv` | each failed simulation with its inputs and simulator messages |
| `metadata.json` | seeds, ranges, versions, git commit, model hash, timings, validation results, current statistics |
| `summary.md` | per-case counts and checks (also copied to `reports/a1_dataset_summary.md`) |

**Validation** runs on every final CSV and checks:
- the row count, column order and that every value is finite;
- every input range, and the Vg/Vb case rule;
- each process parameter is within ±10 % of the correct device's nominal;
- input rows and sample IDs are unique, and no current is exactly zero;
- Kirchhoff's law holds for every row.

### Method
- **Split:** 70/15/15 per case with a fixed seed, saved in `data/transistor/splits.csv`.
  - Test rows are dropped before any fitting.
  - Scalers and target statistics use the training split only.
  - Tuning and model selection use validation only.
  - The test set is evaluated once by a separate script that keeps a record.
- **Features** (`src/leakage/ml.py`): VDD, T in K, log10 W, Vd, Vs, Vds, |Vds|, Vgs, Vgd, Vbs, Vbd, the source offset from its rail, and each process parameter relative to its nominal value.
- **Targets:** all four terminal currents together (multi-output), transformed with `asinh(I/1e-15 A)`. This works like a signed log, keeps the sign and passes smoothly through zero. It was chosen by a validation study (`results/a2/transform_study.csv`):
  - linear targets did far worse;
  - asinh with I₀ = 1e-18, 1e-12 or 1e-9 A did worse;
  - sign classifier + log10|I| did slightly better, but it needs a second model per terminal.
- **Algorithms:** polynomial ridge, random forest, LightGBM and an MLP (L-BFGS, tanh), each grid-searched on validation.
- **Selection:** the lowest mean over Id/Ig/Is/Ib of the validation median relative error.
- **Reproducibility:** every fit uses fixed seeds and exactly 2 BLAS threads, because the thread count changes MLP results. Each saved model stores its metadata (split and dataset hashes, hyperparameters, validation metrics, versions).
- **Error definitions:**
  - Relative error is |I_pred − I_spice| / max(|I_spice|, 1 fA).
  - Absolute error is in A.
  - Scale error is the error divided by the sample's largest terminal current.
  - Sign accuracy counts only samples with |I| ≥ 10 fA.
  - R²_t is R² of asinh(I/1 fA).

## Part B step 3: gate-level SPICE references

```bash
.venv/bin/python scripts/b3_gate_spice.py --smoke   # nominal corner + corner 0, 36 sims, ~10 s
.venv/bin/python scripts/b3_gate_spice.py           # smoke first, then 18 x 200 = 3,600 sims (~5-12 min)
ngspice -b netlists/gates/NAND2.cir
```
- **Gates** (`src/leakage/gates.py`; topologies are stored as data so Part B step 4 and Part C can reuse them):
  - INV, NAND2, NOR2, and AND2/OR2, which are NAND2/NOR2 followed by an inverter and simulated as one netlist.
  - Bodies connect NMOS→0 and PMOS→VDD.
- **Sizing:** the PDF doesn't specify it, so equal-drive sizing is used. The unit inverter has Wn = 90 nm and Wp = 180 nm; series pairs use 2× unit width.
  - INV: N 90 / P 180 nm.
  - NAND2: N 180 (series) / P 180 nm.
  - NOR2: N 90 / P 360 nm (series).
  - Every width lies within the ML training range of 45–360 nm.
- **Corners:** 200 corners in `data/gates/corners.csv`. Each corner has its own RNG, `default_rng([4004, corner_id])`, which draws VDD, T, one NMOS draw of the 5 process parameters and one separate PMOS draw. The same `corner_id`s are used for every gate and will be reused in Part C.
- **Inputs:** exactly 0 or the sampled VDD. Every netlist carries the required `.options` line, and every transistor terminal has a 0 V current probe.
- **Leakage:** `I_leak = Σ_k V_k·(−i(V_k)) / VDD` over the VDD rail and input sources, i.e. static power divided by VDD. It is always positive and includes gate tunnelling drawn from inputs held at VDD. The VDD-rail current alone is stored as `i_vdd`.
- **Outputs:**
  - `data/gates/gate_spice_results.csv`: 3,600 rows with leakage, v(out), x/y/n1 node voltages and checks.
  - `data/gates/gate_spice_devices.csv`: terminal voltages and SPICE currents of every transistor.
  - `failures.csv` and `metadata.json` in the same folder.
  - `results/b3/` (truth table, per-case summary, report).
- **Checks:**
  - 3,600/3,600 converged and 3,600/3,600 truth tables correct.
  - The power from the sources matches Σ V·I over all device terminals to within 1e-6 relative (`reltol`).
- These results are evaluation references only. No model is trained on them.

## Part B steps 4–5: hierarchical ML gate leakage

```bash
.venv/bin/python scripts/b4_gate_ml.py      # ~5 s; no SPICE is run
```
Reuse it, for example in Part C:
```python
from leakage.gate_ml import GateLeakageModel
gm = GateLeakageModel()                   # final transistor models + Part B node voltages
gm.leakage("NAND2", "01", [0, 1, 2])      # predicted I_leak (A) at corners 0..2
```
**Method** (`src/leakage/gate_ml.py`):
- **No gate-level model is trained.** Each transistor's Vd/Vg/Vs/Vb comes from its circuit connections: inputs exactly 0/VDD, bodies on the rails.
- **Internal and output node voltages (out, x, y, n1) are the SPICE-recorded values from step 3**, as the PDF allows. The predictions are therefore *not* independent of SPICE node voltages.
- **ON/OFF model choice:** by gate bias. Gates driven by n1 (the AND2/OR2 inverter) are snapped to the nearest rail; the largest snap is 0.3 mV, and it is recorded.
- **Leakage:** `I_leak = Σ[(Vd−Vs)Id + (Vg−Vs)Ig + (Vb−Vs)Ib] / VDD`, which equals the SPICE definition by Tellegen's theorem.
  - KCL is enforced per device, and each terminal is counted once.
  - Verified by feeding SPICE's own transistor currents through the same code: all 3,600 cases reproduce the SPICE leakage.
- **No hidden SPICE:** inference runs with subprocess execution blocked, with 0 calls attempted (3,600 cases in 0.2 s).

**Results** (`results/b4/`, `reports/b4_gate_ml_report.md`), over 3,600 predictions:

These results use the models of that stage (v2 in all four cases; the final v3 results are in the table at the top):

| Metric | Value |
|---|---|
| Median error | 3.4 % |
| 95th-percentile error | 12.8 % |
| Bias | −0.6 % |
| Mean accuracy | 95.4 % (99 % target not met) |

- **Best:** NAND2 00 (2.4 %) and AND2 00 (2.8 %).
- **Worst:** NOR2 10 (5.8 %) and NOR2 01 (4.0 %).
- **Error source:** OFF transistors at rail biases still dominate the gate error.
- **Earlier run, kept for disclosure:** with v1 OFF models the results were median 4.4 %, p95 21.6 %, mean accuracy 93.1 %. They are archived in `results/b4_archive_off_v1/`, and `reports/a2b_improvement_report.md` explains the switch.
- Full 18-case table: `results/b4/gate_accuracy_18cases.csv`. Parity plot: `results/b4/fig_gate_parity.png`.

## Part C: 3-bit carry-lookahead adder (assigned test circuit)

```bash
.venv/bin/python -m pytest -q tests/test_circuit.py      # exhaustive Boolean tests (Cin = 0 and 1)
.venv/bin/python scripts/c1_cla_spice.py --smoke         # 128 full-circuit sims (~10 s)
.venv/bin/python scripts/c1_cla_spice.py                 # Cin = 0 half: smoke + 64 x 200 = 12,800 sims (~16 min)
.venv/bin/python scripts/c1_cla_spice.py --cin 1         # Cin = 1 half: 12,800 sims into *_cin1 files (~16 min)
.venv/bin/python scripts/c2_cla_ml.py                    # hierarchical ML + evaluation (~30 s)
```
**Circuit** (`src/leakage/circuit.py`, gate list in `data/circuit/cla3_gate_list.csv`, netlist in `netlists/circuit/CLA3.cir`):
- **Logic:** Gi = Ai·Bi, Pi = Ai⊕Bi, C1 = G0 + P0·C0, C2 = G1 + P1·G0 + P1·P0·C0, C3 = G2 + P2·G1 + P2·P1·G0 + P2·P1·P0·C0, Si = Pi⊕Ci.
- **Lookahead:** no carry is computed from another carry (tested).
- **XOR:** built as AND2(OR2, NAND2), with NAND2(Ai, Bi) shared with Gi = INV(·).
- **Size:** 36 gates (15 AND2, 12 OR2, 6 NAND2, 3 INV) and 192 transistors. Widths, bodies, model cards and process draws are the same as Part B.
- **Inputs:** A2..A0, B2..B0 and Cin, so every input combination is 128 vectors (`vector_id = A + 8·B + 64·Cin`). This stage originally simulated the Cin = 0 half (64 vectors, the numbers below); the Cin = 1 half was added in the final audit (`--cin 1`, separate `*_cin1` files), and the final results at the top cover all 128 combinations.

**SPICE reference** (`data/circuit/cla3_spice_results.csv`): the complete 192-transistor netlist at the 200 Part B corners.
- All 12,800 runs converged, and the outputs equal A+B in every one.
- Every internal net is within 0.03 % of VDD of its logic level.
- Leakage uses the same definition as Part B.

**Hierarchical ML** (`data/circuit/cla3_ml_predictions.csv`):
- Boolean simulation gives each gate's inputs, and the Part B gate model gives each gate's leakage. The circuit leakage is the sum over the 36 gates.
- Gate-internal voltages are looked up from the Part B *isolated-gate* SPICE runs. Nothing from the full-circuit SPICE run is used.

| 12,800 cases | Median err | p95 err | Bias | Mean accuracy | R² (log10) |
|---|---|---|---|---|---|
| ML vs full-circuit SPICE | 2.65 % | 10.6 % | −0.8 % | 96.3 % | 0.998 |
| Σ Part B SPICE gates vs full circuit (composition only) | 0.006 % | 0.04 % | −0.006 % | 99.99 % | 1.000 |

Loading turned out negligible here. Nearly all of the error comes from the ML models, and it is *lower* than at gate level because the 36 per-gate errors partly cancel. What remains is a corner-level bias that depends on temperature. Full report: `reports/c_cla3_report.md`; plot: `results/c/fig_cla3_parity.png`.

## Improvement phase (accuracy and reliability)

Full report: `reports/improvement_report.md`. The protocol (`results/improve/selection_rule.md`) was fixed before any experiment ran:
- every decision used **validation only**;
- before and after were scored **once** on new, untouched data (fresh transistor tests, plus 200 new corners with seed 5005 and their own gate and CLA SPICE references);
- original result files and models are preserved. The previous finals are in `trained_models/final_before_improvement/`; Parts B4/C results remain in `results/b4`, `results/c`.

```bash
.venv/bin/python scripts/d1_diagnostics.py                       # error analysis (train/val)
.venv/bin/python scripts/d2_experiments.py --exp E1_ens_v2cache E2_torch_same E5_torch_moredata E6_ens_E2_E5
.venv/bin/python scripts/d2_experiments.py --select --summary    # -> trained_models/v3
.venv/bin/python scripts/d5_op_uniqueness.py --gates data/final_eval/gates data/gates
.venv/bin/python scripts/d3_final_eval.py [--refs corrected]     # one-time before/after
.venv/bin/python scripts/d4_report.py
```
**What limited accuracy:**
- Every earlier MLP stopped at sklearn's 3,000-iteration L-BFGS cap; training error ≈ validation error, so the models were under-fitted.
- **Fix:** the same network trained with PyTorch L-BFGS (`src/leakage/torch_mlp.py`, numpy inference) for 15–20k iterations. On validation, median error fell about 4×.
- After that, the near-rail validation error was 2–18× the training error. So a modest batch of extra targeted transistor samples was added (salt 6).
- An ensemble was selected for NMOS ON.

**Before → after on the new independent data:**

| Level | Median err | p95 err | Mean accuracy |
|---|---|---|---|
| Transistor (spec distribution) | 2.77 % → 0.61 % | 12.0 % → 3.4 % | 95.5 % → 98.6 % |
| Gates (18 × 200, new corners) | 3.80 % → 0.78 % | 13.7 % → 3.0 % | 95.1 % → 98.9 % |
| **3-bit CLA (Cin = 0 half, 64 × 200, new corners)** | 2.98 % → 0.57 % | 10.1 % → 2.3 % | 96.3 % → **99.24 %** |

**99 % target:** reached at circuit level; **not** reached at gate level (98.9 %) or transistor level (98.6 %).

**SPICE reference integrity:** one new-corner gate record had a spurious operating point.
- ngspice's default solve converged to a non-physical internal body-node state, which `d5_op_uniqueness.py` detects using SPICE only.
- It was corrected in a separate file. All other 7,199 gate and all 51,200 CLA references (128 vectors × 200 corners × 2 corner sets) are unique.
- The simulator also now retries isolated non-converging circuits with raised DC iteration limits; this was needed once.

Final transistor models: `trained_models/<case>.joblib` (= `trained_models/v3/`). NMOS ON is an ensemble of two PyTorch MLPs; the other three are single PyTorch MLPs trained with the extra data.
